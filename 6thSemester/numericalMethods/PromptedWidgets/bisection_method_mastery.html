1 Core Idea
What problem does it solve?

Many real-world equations have no closed-form solution — no neat formula to plug numbers into. The Bisection Method finds an approximate root of f(x) = 0 for any continuous function, using a simple but powerful strategy borrowed directly from binary search.

The "aha" intuition: If a continuous curve is below the x-axis at point A and above it at point B, it must cross zero somewhere between them. We keep cutting that gap in half — just like binary search — until we've zeroed in on the crossing.
Why does root-finding matter in CS?

Root-finding is everywhere in your field:

  • Machine learning — finding where a loss function's derivative equals zero
  • Computer graphics — ray-sphere intersection solves quadratic equations; ray-mesh solves harder ones
  • Signal processing — finding where a filter response crosses a threshold
  • Scientific computing — solving transcendental equations like ex = 3x (no algebraic solution)
  • Financial models — finding interest rate given a payment schedule
Analytic vs numerical solutions (from your lecture, slide 6)
Analytic method
  • Gives exact solutions
  • Requires symbolic manipulation
  • Only works when a formula exists
  • Example: quadratic formula for ax² + bx + c = 0
Numerical method (bisection)
  • Gives approximate solutions
  • Converges iteratively — "good enough"
  • Works even when no formula exists
  • Applicable to any continuous f(x)
🧠 Memory hook: Bisection = Binary Search for roots. Both cut the search space in half every iteration. Both guarantee finding the answer in O(log n) steps.
2 Mathematical Foundation
The Intermediate Value Theorem (IVT) — intuition first

Imagine driving from sea level (altitude 0 m) to a mountain peak at 3000 m. You must pass through every altitude in between — you cannot teleport from 0 to 3000 without crossing 1000 m, 2000 m, etc. A continuous function has this exact same property: it cannot jump from negative to positive without crossing zero.

The theorem (Lecture 1, slide 10)

An equation f(x) = 0, where f(x) is a real continuous function, has at least one root between xl and xu if:

f(xl) × f(xu) < 0

This means the function changes sign — one endpoint is negative, the other positive. The curve must cross the x-axis somewhere between them.

The four cases you must know (slides 11–12)
f(xl) × f(xu) < 0 ✓

Signs differ → at least one root guaranteed. Bisection will work.

f(xl) × f(xu) > 0 ✗

Same sign → root may or may not exist. Cannot guarantee. Choose a different bracket.

Same sign but root still exists?

Yes — if there is an even number of roots in the interval (e.g. two roots, signs cancel out).

Signs differ but multiple roots?

Yes — when signs differ, there could be 3, 5… roots. The theorem only guarantees at least one.

Edge case from your lecture (slide 24): f(x) = x² = 0 has a single root at x = 0, but the function touches the x-axis without crossing — it never changes sign. You cannot find two points where f(xl) · f(xu) < 0, so bisection cannot bracket this root. This is called a "tangent root" (even-multiplicity root).
Required conditions for bisection to work
  • f(x) must be continuous on [xl, xu]
  • f(xl) × f(xu) must be < 0 (signs must differ)
  • f(x) must be real-valued on the entire interval

These are called bracketing conditions — bisection is classified as a bracketing method because it always keeps the root trapped inside the interval.

3 The Bisection Algorithm

The exact 6-step algorithm from your Lecture 1, slide 14:

  • 1
    Choose initial bracket
    Choose xl and xu such that f(xl) × f(xu) < 0. This is the sanity check — always verify the signs differ before proceeding. If they don't, your bracket is invalid and you must pick different values.
  • 2
    Estimate the midpoint
    Calculate the midpoint xm as the average of the two endpoints:
    xm = (xl + xu) / 2
  • 3
    Sign check — determine which sub-interval contains the root
    Compute f(xl) × f(xm):
    • If f(xl) × f(xm) < 0 → signs differ → root is in [xl, xm] → set xu = xm
    • If f(xl) × f(xm) > 0 → same sign → root is in [xm, xu] → set xl = xm
    • If f(xl) × f(xm) = 0 → xm IS the root → stop immediately
  • 4
    Update the estimate
    With the updated xl and xu from Step 3, compute the new midpoint:
    xmnew = (xl + xu) / 2
  • 5
    Calculate the approximate relative error
    |εa| = |xmnew − xmold| / |xmnew| × 100%
    On the first iteration there is no previous xm, so εa is undefined — write N/A in your table.
  • 6
    Check stopping condition
    Compare |εa| with the pre-specified tolerance εs:
    • If |εa| > εs → go back to Step 3 and continue
    • If |εa| ≤ εs → stop, xm is your answer
    Also stop if the number of iterations exceeds a maximum limit. Report xm with a warning.
💡 Exam shortcut for the sign check: Instead of computing the actual product f(xl) × f(xm), just check whether f(xl) and f(xm) have different signs. Write "+" or "−" for each and compare — faster and less error-prone.
📌 The update rule in plain English: "xm replaces the endpoint it resembles." If f(xm) has the same sign as f(xl), then xm becomes the new xl. If it has the same sign as f(xu), xm becomes the new xu.
4 Worked Example (from your lecture)
Problem (Lecture 1, slide 15)

Find the root of x³ = 20 using the bisection method. Use initial guesses xl = 1 and xu = 4. Conduct 3 iterations and find the absolute relative approximate error at the end of each iteration.

Step 0 — Setup (slide 16)

Rewrite as f(x) = x³ − 20 = 0. Perform the sanity check:

f(1) = 1³ − 20 = −19  |  f(4) = 4³ − 20 = +44  |  f(1) × f(4) = (−19)(+44) = −836 < 0 ✓

Signs differ → bracket [1, 4] is valid. The true root is ∛20 ≈ 2.71442.

Iteration 1 — xₗ = 1, xᵤ = 4 (slide 17)

Midpoint: xm = (1 + 4) / 2 = 2.5

Evaluate: f(2.5) = (2.5)³ − 20 = 15.625 − 20 = −4.375

Sign check: f(xl) × f(xm) = f(1) × f(2.5) = (−19)(−4.375) = +83.125 > 0

Decision: Same sign → root is NOT in [1, 2.5]. Root is in [2.5, 4]. Set xl = 2.5.

Error: No previous xm → εa = N/A

Iteration 2 — xₗ = 2.5, xᵤ = 4 (slides 18–19)

Midpoint: xm = (2.5 + 4) / 2 = 3.25

Evaluate: f(3.25) = (3.25)³ − 20 = 34.3281 − 20 = +14.3281

Sign check: f(xl) × f(xm) = f(2.5) × f(3.25) = (−4.375)(+14.3281) = −62.69 < 0

Decision: Different signs → root IS in [2.5, 3.25]. Set xu = 3.25.

Error: |εa| = |3.25 − 2.5| / |3.25| × 100 = 0.75 / 3.25 × 100 = 23.08%

Iteration 3 — xₗ = 2.5, xᵤ = 3.25 (slides 20–21)

Midpoint: xm = (2.5 + 3.25) / 2 = 2.875

Evaluate: f(2.875) = (2.875)³ − 20 = 23.7637 − 20 = +3.7637

Sign check: f(xl) × f(xm) = f(2.5) × f(2.875) = (−4.375)(+3.7637) = −16.47 < 0

Decision: Different signs → root IS in [2.5, 2.875]. Set xu = 2.875.

Error: |εa| = |2.875 − 3.25| / |2.875| × 100 = 0.375 / 2.875 × 100 = 13.04%

True root: ∛20 ≈ 2.71442. The interval has narrowed from [1, 4] (width 3.0) to [2.5, 2.875] (width 0.375) — an 8× reduction in just 3 steps.

6 Convergence & Error Analysis
Why the bisection method always converges

Each iteration halves the interval length exactly. Starting with an interval of width b − a:

After n iterations: maximum error ≤ (b − a) / 2n

This is a guaranteed upper bound — no matter how the function behaves, the root cannot be more than this distance from xm. This is why bisection is called unconditionally convergent.

Worked example: Starting from [1, 4], width = 3.
After 10 iterations: error ≤ 3/2¹⁰ = 3/1024 ≈ 0.00293
After 20 iterations: error ≤ 3/2²⁰ ≈ 0.0000029
After 30 iterations: error ≤ 3/2³⁰ ≈ 2.8 × 10⁻⁹
Minimum iterations needed for a target precision

To guarantee an error smaller than ε, you need:

n > log2( (b − a) / ε )

For [1, 4] with ε = 0.0001:  n > log₂(3/0.0001) = log₂(30000) ≈ 14.9 → need at least 15 iterations.

The approximate error formula (slides 8, 14)
|εₐ| = | xmnew − xmold | / | xmnew | × 100%
  • xmnew = midpoint from the current iteration
  • xmold = midpoint from the previous iteration
  • On iteration 1: no previous midpoint, so write N/A
  • Stop when |εa| ≤ εs (your pre-specified tolerance)
Convergence rate

Bisection has linear convergence — each iteration gives exactly one more binary digit of accuracy. In practice, you gain about 0.301 decimal digits per iteration (since log₁₀(2) ≈ 0.301). Compare this to Newton-Raphson, which has quadratic convergence (errors roughly square each step, gaining roughly double the digits per iteration).

Advantages and disadvantages (slides 22–24)
Advantages
  • Always convergent — root is always bracketed
  • Error is bounded and predictable: (b−a)/2ⁿ
  • Simple to implement and understand
  • Only requires function evaluations (no derivatives)
  • Robust — not sensitive to function shape
Disadvantages
  • Slow convergence (linear, not quadratic)
  • If one initial guess is very close to the root, it wastes many iterations
  • Cannot find tangent roots (even multiplicity — e.g. x² = 0)
  • Must manually find an initial valid bracket
  • Does not use all available information about f(x) shape
7 Common Mistakes
✗
Forgetting the sign check. Jumping straight to computing the midpoint without verifying f(xl) · f(xu) < 0. If your bracket is invalid, you will get meaningless results. Always perform this check explicitly and show it in your solution.
✗
Not rewriting the equation as f(x) = 0. Given "solve x³ = 20", students sometimes apply bisection without first writing f(x) = x³ − 20. Always rewrite the equation in the form f(x) = 0 before anything else.
✗
Wrong decision after the sign check. After computing f(xl) · f(xm), confusing which half the root is in. Remember: if the product is < 0 (signs differ), the root is in the left half [xl, xm] → update xu = xm. If > 0 (same signs), root is in the right half [xm, xu] → update xl = xm.
✗
Dividing by the wrong value in the error formula. A common mistake is using xmold in the denominator instead of xmnew. The formula is |xmnew − xmold| / |xmnew| × 100. The denominator is always the current (new) estimate.
✗
Writing εa for the first iteration. In iteration 1, there is no previous midpoint to compare with, so the error is undefined. Always write "N/A" or "—" in your table for iteration 1's error column.
✗
Arithmetic errors in function evaluation. f(2.5) = (2.5)³ − 20: students often compute 2.5² = 6.25 and forget to multiply by 2.5 again. Correct: 2.5 × 2.5 = 6.25, then 6.25 × 2.5 = 15.625, then 15.625 − 20 = −4.375. Write out each multiplication step.
✗
Updating both xl and xu simultaneously. Each iteration updates either xl or xu — never both. The unchanged endpoint remains fixed at its current value.
✗
Applying bisection to discontinuous functions. If f(x) has a vertical asymptote between xl and xu (like 1/x near x = 0), a sign change does not imply a root — it implies a discontinuity. Bisection is only valid for continuous functions.
8 Exam & Problem-Solving Strategy
Step-by-step exam protocol
  1. Rewrite the equation in f(x) = 0 form. Write "f(x) = …" clearly.
  2. Sanity check: compute f(xl) and f(xu), confirm their product is < 0. Show this calculation — examiners want to see it.
  3. Draw your iteration table first with these columns: Iter | xl | xu | xm | f(xl) | f(xm) | Sign product | Update | |εa|%
  4. Fill in row by row. For each iteration: compute xm, evaluate f(xm), check the sign, update the bracket, compute error.
  5. Stop when required (fixed number of iterations or tolerance met).
  6. State the answer: "After n iterations, the approximate root is xm = ___ with |εa| = ___."

Time-saving techniques
  • For the sign check, just write "+" or "−" for each f value and compare visually — no need to compute the actual product
  • Always circle or highlight xm values in your table — they are what the examiner looks for
  • If the problem says "3 iterations", you do not need to check the stopping criterion — just do 3 rows
  • Double-check: the interval width should halve each iteration. If it doesn't, you've made a mistake somewhere
  • For cube roots: compute step by step. 2.875³ = (2.875 × 2.875) × 2.875 = 8.265625 × 2.875 = 23.7637
📝 Viva answer blueprint: "The bisection method is a bracketing root-finding technique based on the Intermediate Value Theorem. We start with an interval [xl, xu] where f(x) changes sign, guaranteeing at least one root by the IVT. Each iteration, we compute the midpoint xm = (xl+xu)/2, evaluate f(xm), and determine which half contains the sign change. That half becomes the new bracket. The interval halves every iteration, guaranteeing linear convergence and a bounded error of (b−a)/2n. The method always converges because the root can never escape the bracket."

Key insight for exams: Bisection is the safest method (always converges, bounded error) but the slowest. Newton-Raphson is the fastest (quadratic convergence) but requires f′(x) and can fail. False Position improves on bisection by using the function's slope, but can stagnate when one bracket barely moves. Secant avoids needing f′(x) while approaching Newton's speed, but is still an open method that can diverge.

The fundamental mental model

Bisection = Binary Search for roots. In binary search, you find a target number by repeatedly halving the search range. In bisection, you find a zero-crossing by repeatedly halving the bracket — using the sign of f(x) as the "which half?" oracle. Both guarantee the answer in O(log n) steps.

Memory tricks
🎯 The sign rule: "If signs differ, the root is between them. If signs are the same, the root escaped to the other half." Think of two people on opposite sides of a fence — if one is above zero and one below, the fence (zero line) must be crossed between them.
📐 The update rule in one sentence: "xm replaces the endpoint it resembles." If f(xm) has the same sign as f(xl), then xm becomes the new xl. If same sign as f(xu), xm becomes the new xu.
⏱️ Convergence pace: Each iteration gives roughly 0.3 more correct decimal digits. For 3 correct decimals: ~10 iterations. For 6 correct decimals: ~20 iterations. For 9 correct decimals: ~30 iterations.
✅ Exam sanity check: After each iteration, verify the interval width has exactly halved. If it hasn't, you made an error in the bracket update.
