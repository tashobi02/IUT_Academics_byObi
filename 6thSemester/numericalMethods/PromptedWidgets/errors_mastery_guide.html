1 Big Picture — Why Errors Matter
The core problem (lecture slide 3)

In any numerical analysis, errors will always arise during calculations. This is unavoidable — whether we are solving a root-finding problem, integrating a function, or differentiating numerically. The goal is not to eliminate errors (impossible) but to:

🔍 Identify

Where is the error coming from? What type is it?

📏 Quantify

How large is the error? Is it acceptable?

⬇️ Minimize

How can we reduce it to meet our tolerance?

This lecture focuses on the first two — identifying and quantifying errors.

Why computers can't represent numbers perfectly

Computers store numbers in binary (base-2) using a finite number of bits. Numbers like 1/3 = 0.333333… or π = 3.14159… require infinite digits. A finite register must truncate them — this is the root cause of round-off error. Every time you do arithmetic on a computer, you are operating on approximate values.

Analogy: Imagine measuring a 1/3 cup of flour with a measuring cup that only shows 2 decimal places. You pour 0.33 cups. That 0.00333… you lost every time adds up over a recipe with 20 such steps — eventually your bread comes out wrong. Computers face the same problem at scale.
Real-world consequences of numerical errors
⚠️ Ariane 5 Rocket (1996)

A 64-bit float was incorrectly converted to a 16-bit integer. The overflow caused the guidance system to crash. The rocket self-destructed 37 seconds after launch. Loss: $500 million.

⚠️ Patriot Missile (1991)

A round-off error in time representation (1/10 second) accumulated over 100 hours = 0.34 second tracking error. A Scud missile was not intercepted. 28 soldiers killed.

🧠 The mindset shift: In pure math, 1/3 + 1/3 + 1/3 = 1. In computer arithmetic, it might be 0.9999999999999999. That tiny gap is what this entire lecture is about.
2 Types of Errors
2A · True Error (Et) — slides 4–8
Definition

True error Et is the difference between the true (exact) value and the approximate value. Also called the exact error or ground truth error.

Et = True Value − Approximate Value
Intuition

Think of archery. The bullseye is the "true value." Where your arrow actually lands is the "approximate value." The distance between them is the true error. Et can be positive (you undershoot) or negative (you overshoot).

⚠️ The problem with true error alone

Et = −0.749 seems small. But for a function of order 10−6, the same problem gives Et = −0.749 × 10−6. The error magnitude alone does not tell you how bad the approximation is. We need scale invariance — enter relative error.

2B · Relative True Error (εt) — slides 9–10
Definition

The ratio of the true error to the true value. It tells you what fraction of the true value your error represents.

εt = True Error / True Value = Et / True Value
Percentage form: |εt| × 100%
Intuition: Missing by 1 kg when weighing a 1000 kg elephant is acceptable (0.1% error). Missing by 1 kg when weighing a 2 kg baby is catastrophic (50% error). The relative error captures this context — same absolute error, completely different significance.
2C · Approximate Error (Ea) — slides 11–14
The Practical Problem

When solving a problem numerically, we will only have access to approximate values — we don't know the true answer! (If we did, we wouldn't need numerical methods.) So we measure error by comparing successive iterations.

Ea = Present Approximation − Previous Approximation
Intuition

If you are iteratively zooming in on an answer, the difference between your current guess and previous guess tells you how much you've still changed. When this gap is tiny, you've converged.

Same limitation as Et

Again, magnitude alone is misleading. Ea = −0.383 might be large for a problem with answers near 1, but tiny for a problem with answers near 1,000.

2D · Relative Approximate Error (εa) — slides 15–16
Definition — the most important formula in iterative methods

Ratio of approximate error to the present approximation. This is the formula from Lecture 1's bisection method stopping criterion.

εa = Ea / Present Approximation = (xmnew − xmold) / xmnew
Percentage form: |εa| × 100%
Absolute form: |εa| = |Present − Previous| / |Present| × 100%

3 Sources of Errors

Error in solving an engineering or science problem can arise from several factors (slide 24):

General sources
  • Modeling technique — the mathematical model uses assumptions that are not perfectly valid
  • Mistakes in programs — bugs in code, incorrect implementation
  • Measurement errors — physical quantities have measurement uncertainty
The two inherent numerical sources

In applications of numerical methods themselves, the two errors we focus on are:

  • Round-off Error — caused by approximating numbers
  • Truncation Error — caused by approximating mathematical procedures
3A · Round-off Error (slide 25)
What it is

A computer can only represent a number approximately. Computers store numbers in binary using a finite number of bits. Many real numbers need infinitely many digits (binary or decimal) and must be chopped or rounded to fit in finite memory.

Classic examples
  • 1/3 = 0.333333… → stored as 0.333333 → error = 0.0000003̄
  • π = 3.14159265… → approximated in every program
  • √2 = 1.41421356… → irrational, can never be exact
Why it happens

Computers store numbers in registers with a finite number of bits. A 64-bit float has 52 bits of mantissa — about 15-17 significant decimal digits. Any number requiring more precision is automatically rounded. Computers would need infinite bits to be exact.

🧠 Memory trick: Round-off = rounding a number to fit in memory. Think of it as chopping the tail off an infinite decimal to make it fit in your pocket.
3B · Truncation Error (slides 26–31)
What it is

Truncation error is the error caused by approximating a mathematical procedure. It arises when we replace an exact mathematical operation (infinite series, infinitesimal limit) with a finite approximation.

Three classic examples from your lecture:

  • 1
    Chopping an infinite series
    The Maclaurin series for eˣ is: ex = 1 + x + x²/2! + x³/3! + x⁴/4! + … (infinite terms)
    If we use only 3 terms: ex ≈ 1 + x + x²/2!
    Truncation error = x³/3! + x⁴/4! + … (all the dropped terms)
  • 2
    Finite step size for derivatives
    The exact definition of a derivative requires h → 0: f′(x) = limh→0 [f(x+h)−f(x)]/h
    In numerical methods, we use a finite h: f′(x) ≈ [f(x+h)−f(x)]/h
    Truncation error is caused by using a finite h instead of h → 0.
    Example: f(x) = x², f′(3) = 6 (exact), with h = 0.2: f′(3) ≈ (3.2²−3²)/0.2 = 1.24/0.2 = 6.2 → Truncation error = 6 − 6.2 = −0.2
  • 3
    Finite rectangles for integration
    The exact integral ∫39 x² dx = [x³/3]39 = (729−27)/3 = 234
    Using 2 rectangles of equal width: (3²)(3) + (6²)(3) = 27 + 108 = 135
    Truncation error = 234 − 135 = 99 (huge — only 2 rectangles is a poor approximation!)
💡 Memory trick: Truncation = truncating (cutting short) a procedure. The procedure wants to go to infinity (infinite series, h→0, infinite rectangles), but you stop it early.
Round-off vs Truncation — the key difference
Round-off Error

Error in representing numbers. Caused by finite memory. Reduced by using more bits (double vs single precision). Cannot be eliminated entirely.

Truncation Error

Error in approximating procedures. Caused by finite terms/steps. Reduced by using more terms or smaller step size h. Can be made arbitrarily small in principle.

4 Significant Digits & Accuracy
What are significant digits? (slides 17–19)

Significant figures (also called significant digits, precision, or resolution) are the digits in a number that are reliable and necessary to indicate the quantity. These are the digits you can actually trust.

Practical example from your lecture

Thermal expansion coefficient of steel = 6.47 μin/in/°F = 0.00000647 in/in/°F
If written to 2 decimal places: 0.00 in/in/°F — all the information is lost!
This is why engineering uses scientific notation: 6.47 × 10−6 preserves all 3 significant digits.

The 4 rules for counting significant digits (slide 18)
  • 1
    Non-zero digits are ALWAYS significant
    1, 2, 3, 4, 5, 6, 7, 8, 9 — every non-zero digit counts. In 2.789, all 4 digits are significant.
  • 2
    Zeros BETWEEN non-zero digits are ALWAYS significant
    4008 has 4 significant digits (the two zeros are sandwiched between 4 and 8). 4208.07 has 6 sig digits.
  • 3
    LEADING zeros are NEVER significant
    0.0439 has only 3 sig digits (4, 3, 9). The leading zeros just mark the position of the decimal — they carry no information.
  • 4
    TRAILING zeros are significant ONLY if the number has a decimal point
    4.590 has 4 sig digits (trailing zero after decimal is significant). 78800 has only 3 (ambiguous). 78800. has 5 (explicit decimal point signals all zeros are significant).
Significant digit examples (from lecture quiz, slides 20–21)
Exact numbers have infinite significant digits (slide 19)

If you have exactly 5 books, that's 5.000000… — an infinite number of significant digits. Exact counted quantities are not limited by measurement precision.

The key relationship: εa and significant digits (slides 22–24)
Critical formula — memorise this

If you want at least m significant digits to be correct in your answer, you need the absolute relative approximate error to satisfy:

|εa| ≤ 0.5 × 10(2 − m) %

Equivalently: stop iterating when |εa| ≤ εs = 0.5 × 10(2−m)%

5 Floating Point & Computer Representation
Why computers introduce round-off error

All modern computers use the IEEE 754 floating-point standard. A number is stored as: ±1.fraction × 2exponent. The "fraction" part has a fixed number of bits (52 bits in double precision). This means only numbers expressible in this form can be stored exactly. Everything else must be rounded.

What CAN'T be stored exactly
  • Any fraction whose denominator isn't a power of 2
  • 1/3, 1/5, 1/6, 1/7, 1/9, 1/10…
  • Irrational numbers: π, √2, e, ln(2)…
  • Very large numbers: 10300 may overflow
  • Very small differences: catastrophic cancellation
What CAN be stored exactly
  • Integers (within range)
  • Fractions with power-of-2 denominators: 1/2, 1/4, 3/8…
  • Small integers: 0, 1, 2, 3, ..., 253

Even 0.1 cannot be stored exactly in binary! It repeats: 0.0001100110011…

Binary representation — the intuition

Just as 1/3 in decimal = 0.333… (repeating), many simple fractions in decimal become repeating in binary:

0.1 (decimal) = 0.000110011001100110011… (binary, repeating forever)

A 64-bit double stores about 52 bits of the fraction — then it stops. The leftover is your round-off error.

Chop vs Round (slide 25)
Chopping (truncation to n digits)

Simply drop all digits past position n. 0.333333… → 0.333333. Always introduces error in one direction (always makes number smaller in magnitude). Asymmetric bias.

Rounding (to n digits)

Look at digit n+1. If ≥ 5, round up the last kept digit. 0.333333… → 0.333333 (same here). 3.14159 → 3.1416 (round up). More balanced — errors can go either direction.

The dilemma: smaller h doesn't always mean better (slide 31)
For the numerical derivative f′(x) ≈ [f(x+h)−f(x)]/h: making h very small reduces truncation error but increases round-off error (because f(x+h) and f(x) become very similar, and their difference loses significant digits — "catastrophic cancellation"). There is an optimal h.
6 Error Propagation
How small errors spread through calculations

When you perform a sequence of arithmetic operations on approximate numbers, each operation can amplify, shrink, or compound the errors. This is called error propagation.

Addition / Subtraction

Errors add roughly: Δ(a±b) ≈ Δa + Δb. If a and b are close in value and you subtract them, relative error can explode — catastrophic cancellation.

Multiplication / Division

Relative errors add: Δ(ab)/ab ≈ Δa/a + Δb/b. A 0.01% error in both a and b gives roughly 0.02% relative error in their product.

Catastrophic cancellation — the silent killer
Example

Suppose the true values are a = 1.000001 and b = 1.000000, and your computer stores both rounded to 6 significant digits: â = 1.00000, b̂ = 1.00000.
Then â − b̂ = 0, but the true a − b = 0.000001. You've lost all your significant digits in one subtraction!

Why repeated operations amplify errors

In iterative numerical methods (bisection, Newton-Raphson etc.), each iteration involves multiple operations. Errors compound:

  • Each function evaluation has round-off error
  • Each arithmetic operation introduces another tiny error
  • Over hundreds of iterations, these accumulate
  • Well-designed algorithms are stable — errors don't grow exponentially
  • Poorly designed algorithms are unstable — tiny initial error grows to dominate the result
🧠 Key insight: Numerical stability is why we care about the ORDER in which we perform operations, not just the operations themselves. (1000000 + 1) − 1000000 gives a very different floating-point result than 1000000 − 1000000 + 1, even though both equal 1 in exact arithmetic.
7 Worked Examples
Example 1 — True Error (from lecture, slides 5–7)
Problem

For f(x) = 7e0.5x, using the finite difference approximation f′(x) ≈ [f(x+h)−f(x)]/h with h = 0.3, find: (a) approximate value of f′(2), (b) true value of f′(2), (c) true error.

Solution

Part (a) — Approximate value:

f′(2) ≈ [f(2+0.3) − f(2)] / 0.3 = [f(2.3) − f(2)] / 0.3
= [7e0.5(2.3) − 7e0.5(2)] / 0.3
= [7e1.15 − 7e1.0] / 0.3
= [22.107 − 19.028] / 0.3
= 3.079 / 0.3 = 10.263

Part (b) — True value (using calculus):

f(x) = 7e0.5x → f′(x) = 7 × 0.5 × e0.5x = 3.5e0.5x
f′(2) = 3.5 × e0.5(2) = 3.5 × e1 = 3.5 × 2.71828 = 9.5140

Part (c) — True error:

Et = True value − Approximate value = 9.5140 − 10.263 = −0.749
The negative sign means we overestimated — our approximation (10.263) is above the true value (9.5140). The finite step h = 0.3 is too large; the secant line slope overshoots the tangent.
Example 2 — Relative True Error (slide 10)
Continuing from Example 1
εt = True Error / True Value = −0.749 / 9.5140 = −0.078726
Percentage: εt = −0.078726 × 100% = −7.8726%
Absolute: |εt| = 7.8726%
Now we can properly interpret the error: Our approximation is off by 7.87% of the true value. This is meaningful regardless of the scale of f(x). For a function 106 times smaller, the relative error would still be 7.87%.
Example 3 — Approximate Error (slides 12–13)
Problem

For f(x) = 7e0.5x, compute f′(2) using h = 0.3 and h = 0.15. Find the approximate error for the h = 0.15 estimate.

Solution

f′(2) with h = 0.3 (previous approximation): = 10.263 (from Example 1)

f′(2) with h = 0.15 (present approximation):

f′(2) ≈ [f(2.15) − f(2)] / 0.15 = [7e1.075 − 7e1.0] / 0.15
= [20.510 − 19.028] / 0.15 = 1.482 / 0.15 = 9.8800

Approximate Error:

Ea = Present Approximation − Previous Approximation
= 9.8800 − 10.263 = −0.38300
Example 4 — Relative Approximate Error (slide 16)
Solution (continuing from Example 3)
εa = Ea / Present Approximation = −0.38300 / 9.8800 = −0.038765
Percentage: εa × 100% = −3.8765%
Absolute: |εa| = 3.8765%
Example 5 — Significant digits from Maclaurin series (slides 23–24)
Problem

Use 6 terms of the Maclaurin series for eˣ to compute e0.7. How many significant digits can be trusted? (Without knowing the true answer.)

Solution

5-term approximation (previous):

e0.7 ≈ 1 + 0.7 + (0.7²/2!) + (0.7³/3!) + (0.7⁴/4!) = 1 + 0.7 + 0.245 + 0.0572 + 0.01 = 2.0122

6-term approximation (current):

e0.7 ≈ 2.0122 + (0.7⁵/5!) = 2.0122 + 0.0014 = 2.0136

Absolute relative approximate error:

|εa| = |2.0136 − 2.0122| / 2.0136 × 100% = 0.0014/2.0136 × 100% = 0.069527%

How many significant digits are correct?

Need: |εa| ≤ 0.5 × 10(2−m)% For m=2: 0.5 × 100 = 0.5% — is 0.069527% ≤ 0.5%? YES ✓ For m=3: 0.5 × 10−1 = 0.05% — is 0.069527% ≤ 0.05%? NO ✗ ∴ At least 2 significant digits are correct in the answer 2.0136
(Verification: true e0.7 ≈ 2.01375 — indeed, "2.0" matches, but the third digit is not reliable.)
Example 6 — Truncation error for derivative (slide 30)
Problem: f(x) = x², find f′(3) numerically with h = 0.2
f′(3) = 2x|x=3 = 6 (exact, from calculus)

Numerical approximation: f′(3) ≈ [f(3.2) − f(3)] / 0.2 = [(3.2)² − (3)²] / 0.2 = [10.24 − 9] / 0.2 = 1.24/0.2 = 6.2

Truncation Error = Exact Value − Approximate Value = 6 − 6.2 = −0.2
Reducing h would reduce this truncation error — but too small h causes round-off error to dominate. There's an optimal h.

How the relative error links to scale invariance

True Error Et = −0.749 for both f(x) = 7e0.5x and f(x) = 7×10−6e0.5x.
But the Relative True Error |εt| = 7.87% for BOTH cases.
This is why relative error is the correct measure — it's scale-invariant. The error as a fraction of the true value is the same regardless of how large or small the quantities are.

Mental model: the three zones of a number
🎯 Zero error zone

Et = 0, |εa| = 0. Perfect answer. Impossible in general with finite-precision computers.

✅ Acceptable zone

|εa| ≤ εs (below tolerance). Enough significant digits for your purpose. Stop iterating.

⚠️ Unacceptable zone

|εa| > εs. Not enough significant digits yet. Keep iterating or use more terms.

9 Common Mistakes
⚠️ Mistake 1: Confusing Et with εt
Et is the raw error (units preserved). εt is the dimensionless ratio. Always check: does the problem ask for the error, the relative error, or the percentage relative error? These are three different answers.
⚠️ Mistake 2: Wrong denominator in relative error
εt = Et / True Value (not approximate value). εa = Ea / Present (current) approximation (not previous). Mixing these up is the #1 formula error.
⚠️ Mistake 3: Forgetting the absolute value
Relative errors are often reported as absolute values |εt| and |εa|. The sign of the error tells you direction (overestimate vs underestimate), but for comparing against tolerance, you use the absolute value. Always apply |…| when comparing to εs.
⚠️ Mistake 4: Wrong formula for Ea
Ea = Present − Previous (not Previous − Present, not |Present| − |Previous|). The order matters because the sign tells you if you went up or down in successive approximations.
⚠️ Mistake 5: Confusing truncation error with round-off error
Students often say "we stopped at n terms so that's round-off error." No — cutting a series short is truncation error. Round-off error is about finite bit representation of individual numbers. Keeping more terms reduces truncation; using double precision reduces round-off.
⚠️ Mistake 6: Counting significant digits incorrectly
"0.0045 has 4 significant digits" — WRONG. Leading zeros are never significant. 0.0045 has only 2 significant digits (4 and 5). Write it in scientific notation to avoid confusion: 4.5 × 10−3.
⚠️ Mistake 7: Assuming lower Et always means better approximation
As your lecture emphasises (slide 8): a low true error does NOT necessarily mean a good approximation. A true error of 0.001 for a function of order 10−6 would be catastrophic. Always use relative error for interpreting "how good is my approximation."
⚠️ Mistake 8: Significant digits in 78800 vs 78800.
78800 (no decimal point) = 3 significant digits (ambiguous trailing zeros). 78800. (with explicit decimal) = 5 significant digits. The decimal point is the signal.
10 Problem-Solving Strategy
The universal exam protocol for error problems
  • 1
    Read carefully — identify what's asked
    Is it Et, εt, Ea, or εa? As a percentage? As an absolute value? Write down the formula before calculating.
  • 2
    Identify your values
    Label: true value, approximate value, present approximation, previous approximation. Write them clearly before substituting into formulas.
  • 3
    Apply the correct formula
    Et = True − Approx. εt = Et/True. Ea = Present − Previous. εa = Ea/Present. Double-check your denominator every time.
  • 4
    Check sign vs absolute value
    The question may ask for the signed value or |…|. Report both if unsure: e.g. "εt = −7.87%, |εt| = 7.87%"
  • 5
    For significant digits: use the tolerance formula
    To check m correct digits, verify |εa| ≤ 0.5 × 10(2-m)%. Check m=1, 2, 3… until the condition fails. The largest m that satisfies it is your answer.
Fast calculation tricks
  • For εt: compute Et first, then divide by true value. Don't mix the formulas.
  • For the tolerance formula: 0.5 × 10(2−m)% means 5%, 0.5%, 0.05%, 0.005% for m = 1, 2, 3, 4. Memorise this row.
  • Significant digits: write the number in scientific notation — all digits in the coefficient are significant.
  • If given two approximations and asked for |εa|: always divide by the more recent / smaller step size / more terms value.
  • Et negative → you overestimated. Et positive → you underestimated. Useful for self-checking.
📝 Viva answer for "what is relative error and why do we need it?"
"Relative error is the ratio of the true error to the true value, expressed as a fraction or percentage. We need it because the magnitude of the true error alone is not interpretable without context — an error of 1 unit is catastrophic when the true value is 2, but negligible when it is 1,000,000. The relative error provides scale-invariant measurement of approximation quality."

HardP5 (Conceptual): Explain why making the step size h extremely small (e.g. h = 10−20) does NOT improve the numerical derivative. What two competing errors are involved?
▾

This is the tension between truncation error and round-off error in numerical differentiation:

Truncation Error decreases as h → 0

The formula f′(x) ≈ [f(x+h)−f(x)]/h gets more accurate as h shrinks. The truncation error for forward difference is O(h) — proportional to h. Smaller h = smaller truncation error.

Round-off Error INCREASES as h → 0

f(x+h) and f(x) become very close. Their difference f(x+h)−f(x) becomes very small. But both values have inherent round-off errors of order εmachine ≈ 10−16. When we divide a tiny difference by h, we amplify the round-off. As h → 10−20, the numerator is dominated by noise.

Optimal h: There's an optimal h ≈ √εmachine ≈ 10−8 that minimises total error. This is why taking h = 10−20 is a terrible idea — you can't calculate that many bits of precision!

This is why lecture slide 31 asks: "Is it a good idea to take h = 10−20?" The answer is NO — computers cannot represent the difference between x and x + 10−20 in finite precision, so you'd effectively compute [f(x) − f(x)] / h = 0/h = 0, which is wildly wrong.
ConceptualP6: A student computes two approximations: x₁ = 1000.1 and x₂ = 1000.0 (previous). The approximate error is Ea = 0.1. Another student computes x₁ = 0.0001 and x₂ = 0.0000 (previous), Ea = 0.0001. Which approximation is better and why?
▾

Student 1: |εa| = |0.1 / 1000.1| × 100 = 0.00999% → extremely good!

Student 2: |εa| = |0.0001 / 0.0001| × 100 = 100% → terrible!

Even though Student 2's absolute error (0.0001) is much smaller than Student 1's (0.1), the relative approximate error tells a completely different story. Student 1 has a 0.01% relative error; Student 2 has 100%. Student 1's approximation is orders of magnitude better.

This demonstrates exactly why your lecture emphasises: "A low approximate error doesn't necessarily translate to a good approximation. We need scale invariance — the relative error."

13 Summary & Mental Models
The big-picture mental model

Numerical errors are unavoidable — our job is to measure and control them. Three steps: Identify (where does it come from?), Quantify (how large is it?), Minimize (can we reduce it?). This lecture gives you the vocabulary and formulas for identifying and quantifying.

Memory tricks
🎯 Et vs εt: "E is the raw Error (in units). ε is the fraction (epsilon = 'fractional part'). Divide E by the True value to get ε." Same pattern: Ea → εa by dividing by the Present approximation.
🎯 Present vs Previous: For Ea = Present − Previous: "you report how much you moved from where you were." For εa: "you normalise by where you are now (present)."
🎯 Round-off vs Truncation: "Round-off rounds a NUMBER (memory limit). Truncation truncates a PROCEDURE (stopping the math early)."
🎯 Sig digits tolerance table: 5%, 0.5%, 0.05%, 0.005%… just keep dividing by 10. Want 1 digit → 5%. Want 2 → 0.5%. Want 3 → 0.05%.
🎯 Leading zeros never count: "Zeros before the first non-zero are just decimal placeholders, like leading zeros in a phone number." 0.0047 → the zeros are just telling you how small it is. Only 4 and 7 matter.
Key concepts at a glance
True Error
Known when true answer is available. True − Approx. Can be +/−.
Relative True Error
Scale-invariant. Fraction of true value that's wrong. Works for any scale.
Approximate Error
Used when true value unknown. Compares successive iterations.
Relative Approx. Error
The stopping criterion in iterative methods. |εa| ≤ εs → stop.
Significant Digits
Reliable digits. 4 rules. Leading zeros don't count. Use sci notation.
Round-off Error
Finite bits → approximate numbers. Reduced by higher precision (64-bit).
Truncation Error
Approximate procedures. Series, h→0, rectangles. Reduced by more terms/steps.
Sig digits formula
|εa| ≤ 0.5 × 10(2−m)% guarantees m correct digits.
